# Manual QA Plan — 2026-03-17

First-ever manual QA of the jujo CLI. Focuses on multi-language support (Rust, Go, Python, TypeScript),
the full agent protocol workflow, and adversarial input handling.

## Setup

```bash
export JUJO="$HOME/Desktop/code/jujo/target/release/jujo"
export QA_DIR="/tmp/jujo-qa"
cargo build --release
```

Each test group works in a fresh temp directory unless noted otherwise.

## Group 2: Generate — Happy Path (TC-10 to TC-19)

Setup: create a minimal generator in each language's init'd project.

```bash
# For each language, after init:
mkdir -p .jujo/templates/module
cat > .jujo/templates/module/generator.toml << 'EOF'
[generator]
name = "module"
description = "A basic module"

[[inputs]]
name = "module_name"
type = "string"
required = true

[[inputs]]
name = "fields"
type = "field[]"
required = true

[[actions]]
type = "create"
template = "entity.tera"
output = "src/{{ module_name }}/entity.txt"
EOF
```

## Priority Order

Execute in this order (highest value first):

1. **Group 8: Cross-Command Workflows** (TC-73..80) — proves the core agent protocol works end-to-end across languages
2. **Group 4: Generate Errors** (TC-30..42) — catches panics, security issues
3. **Group 1: Init** (TC-01..09) — validates multi-language foundation
4. **Group 3: Injection** (TC-20..29) — marker system is complex, high bug potential
5. **Group 2: Generate Happy** (TC-10..19) — basic functionality across languages
6. **Group 6: Validate** (TC-53..62) — template error reporting quality
7. **Group 5: List & Describe** (TC-43..52) — JSON protocol correctness
8. **Group 7: Template Management** (TC-63..72) — lower risk
9. **Group 9: Hooks** (TC-81..85) — narrow scope

## Template Fixtures Needed

For cross-language testing, we need a shared generator template that exercises:
- Name derivation (pascal_case, snake_case)
- Field iteration with type mapping
- Nullable fields
- Conditional sections (bool input)
- AI customization markers
- Injection with correct comment style

Create one `entity.tera` template that works across languages by using the type_map:

```
{%- set entity_name = module_name | singularize -%}
{%- set EntityName = entity_name | pascal_case -%}
// Entity: {{ EntityName }}
{%- for field in fields %}
// field: {{ field.name }} ({{ field.mapped_type }}{% if field.nullable %}, nullable{% endif %})
{%- endfor %}
// <ai:customize hint="Add domain logic for {{ EntityName }}">
// placeholder
// </ai:customize>
```

This language-neutral template (using `//` comments) tests the core rendering. Language-specific templates (using actual syntax) are needed for TC-73..76.
