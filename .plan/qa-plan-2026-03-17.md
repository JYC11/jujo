# Manual QA Plan — 2026-03-17

First-ever manual QA of the jujo CLI. Focuses on multi-language support (Rust, Go, Python, TypeScript,
HTML, CSS), the full agent protocol workflow, and adversarial input handling.

## Setup

```bash
export JUJO="$HOME/Desktop/code/jujo/target/release/jujo"
export QA_DIR="/tmp/jujo-qa"
cargo build --release
```

Each test group works in a fresh temp directory unless noted otherwise.

name = "module_name"

[[inputs]]
name = "fields"

required = true

## Language Testability Audit

Which languages can we actually verify generated code for (compile/parse)?

| Language | Testable Locally? | Tool Needed | Notes |
|----------|-------------------|-------------|-------|
| Rust | Yes | rustc/cargo | Already available on macOS |
| Go | Depends | go | Install via brew |
| Python | Yes | python3 | Pre-installed on macOS |
| TypeScript | Depends | tsc/node | npm install typescript |
| HTML | Yes | - | Just validate well-formedness, or use `tidy` |
| CSS | Yes | - | Can validate syntax with `stylelint` or just check structure |
| C# | No (without .NET) | dotnet | Docker: mcr.microsoft.com/dotnet/sdk |
| Java | Depends | javac | Might be installed, or use Docker |
| Kotlin | No | kotlinc | Docker: gradle or kotlin image |
| Swift | Yes (on macOS) | swiftc | Pre-installed on macOS |
| Ruby | Depends | ruby | Might be pre-installed on macOS |
| PHP | Depends | php | brew install php |
| Elixir | No | elixir | Docker: elixir image |

### Tiers

- **Tier 1 (always testable)**: Rust, Python, HTML, CSS, Swift (macOS)
- **Tier 2 (likely available or easy install)**: Go, TypeScript, Ruby, PHP, Java
- **Tier 3 (Docker required)**: C#, Kotlin, Elixir

### Tier 3 Docker-based testing

For languages that aren't locally available, use Docker to verify generated code compiles:

```bash
# Example: verify C# code compiles
docker run --rm -v $(pwd)/generated:/src mcr.microsoft.com/dotnet/sdk:8.0 dotnet-script /src/order.cs

# Example: verify Kotlin code compiles
docker run --rm -v $(pwd)/generated:/src gradle:jdk17 kotlinc /src/order.kt -include-runtime -d /tmp/out.jar

# Example: verify Elixir code parses
docker run --rm -v $(pwd)/generated:/src elixir:1.16 elixir -e "Code.compile_file(\"/src/order.ex\")"
```

## Template Fixtures Needed

For cross-language testing, we need a shared generator template that exercises:
- Name derivation (pascal_case, snake_case)
- Field iteration with type mapping
- Nullable fields
- Conditional sections (bool input)
- AI customization markers
- Injection with correct comment style

Create one `entity.tera` template that works across languages by using the type_map:

```
{%- set entity_name = module_name | singularize -%}
{%- set EntityName = entity_name | pascal_case -%}
// Entity: {{ EntityName }}
{%- for field in fields %}
// field: {{ field.name }} ({{ field.mapped_type }}{% if field.nullable %}, nullable{% endif %})
{%- endfor %}
// <ai:customize hint="Add domain logic for {{ EntityName }}">
// placeholder
// </ai:customize>
```

This language-neutral template (using `//` comments) tests the core rendering. Language-specific templates (using actual syntax) are needed for TC-81..86.
